# WorkCore E6 首发生态与场景验证控制书

状态：E6 北极星愿景的首发量产约束、设计伙伴准入与产品存在性验证输入。本文不是测试完成声明；所有阈值都必须由带版本号的样机、场地、软件、路线和原始记录闭环。未取得证据的能力保持为“未放行”，不得转写成宣传语。

关联文件：[E6 产品定义与策略](e6_product_definition_and_strategy.md)、[成熟产品基准矩阵](benchmark_matrix.md)。若愿景叙事与本文的首发边界冲突，以更窄、更安全、可服务的边界为准。

## 0. 决策摘要：北极星不变，首发楔子收窄

E6 的北极星仍是“家—社区—咖啡馆—家之间保持工作连续性的个人移动智能工作伴体”。首发却不直接进入任意家庭、公共道路或无管理公共空间，而采用受控的 **B2B2C 设计伙伴/租赁服务**：

- 预算方是愿意为高价值创作、研发或现场任务连续性付费的企业、工作室、园区、实验室或运营场所；
- 使用者是一天内确实多次在固定私域路线中移动、布置并恢复数字任务的人；
- 场地方共同承担路线、充电、日检、人员培训和救援，不把一台 E6R2 遗留收纳态模型已约 113kg、且 E6-DFR4 量产基础 SKU 总质量尚未冻结的机器当成普通消费电子交付后即结束；
- WorkCore/设计伙伴保留设备所有权或回收权，以付费试点、期限租赁和托管服务验证价值、可靠性与服务成本；
- 首发只放行经过测绘、白名单化、风险评估和现场演练的 ODD。家庭—社区—咖啡馆是后续扩张方向，不是首批商业交付承诺。

这个楔子的目的不是降低产品野心，而是先证明三件事：用户真的频繁失去工作上下文；四态切换能比替代方案更低摩擦；场地方能以可承受的成本运营、救援和维护整机。

## 1. 首发 ICP、买方与生态位冻结

### 1.1 正向 ICP

首发使用者需同时满足以下条件：

1. 在同一受控场所内，每个有效工作日至少出现 3 次“必须离开当前工位、携带设备或重新布置、随后恢复同一任务”的合格中断；
2. 任务恢复包含文件、窗口、外设、身份、隐私或身体姿态中的至少两项，不只是把笔记本从 A 桌搬到 B 桌；
3. 单次中断造成的时间、注意力或体力损失可以被观察和计价；
4. 能独立或在普通工作协助下安全乘坐、离座和管理个人物品，不依赖 WorkCore 提供医疗或照护功能；
5. 愿意接受路线限制、培训、事件记录和试点期研究。

优先人群是创作、AI/机器人研发、影音制作、实验室/样机调试、园区现场知识工作者，以及因疲劳或轻度活动受限而更看重低摩擦移动的人。后者不等于医疗器械定位，任何康复、护理或疾病获益声明均不在首发范围。

### 1.2 预算方、签约方与运营方

| 角色 | 首发冻结 | 必须提供的证据 |
|---|---|---|
| 预算方/签约方 | 企业创新、员工体验、设施、研发运营、工作室或园区运营负责人 | 有明确预算科目；能签付费试点、租赁或带预算额度的意向；能说明不用 WorkCore 时的替代成本 |
| 日常运营方 | 场地设施/安全人员或指定设备管理员 | 有值班窗口、日检责任、停放/充电位置和救援联系人 |
| 设计伙伴 | 允许共同冻结路线、服务与数据边界的早期客户 | 接受现场观察、配置冻结、事件复盘和不满足门槛时停用 |
| 最终使用者 | 满足 1.1 的高频任务切换者 | 完成培训；独立通过四态、隐私、急停和恢复考核 |
| WorkCore 服务方 | 产品、现场服务、安全、隐私与软件责任主体 | 提供版本清单、风险文件、备件、事件闭环和退出/召回路径 |

### 1.3 明确排除的首发客户

- 主要需求是固定工位人体工学的人；
- 需要道路通行、楼梯、自动电梯/门、密集人群或无人跨楼层配送的场地；
- 把产品当作轮椅、护理设备、无人看护设备或应急转运设备的买方；
- 无法提供固定充电点、路线控制、现场联系人或救援器材的场地；
- 只愿意接受一次性硬件采购、拒绝试点数据与服务约束的首批客户；
- 无法证明每天至少 3 次合格中断，或一张桌、一把椅、推车、笔记本支架即可更经济解决的用户。

## 2. 首发商业、交付、服务与救援假设

以下是量产验证的冻结假设，不是永久商业模式。任何变更都必须重新评估 COGS、责任边界、培训、路线和救援。

| 项目 | 首发基线 | 不允许的偷换 |
|---|---|---|
| 商业模式 | 先付费试点，再期限租赁/托管服务；设备可回收、换机和远程停用 | 用免费体验、口头兴趣或媒体曝光替代支付意愿 |
| 价值单位 | 每个有效工作日避免的合格中断、恢复时间、体力负担与场地重布置成本 | 只统计展开桌面的“惊艳感” |
| 报价 | 同时列硬件摊销、交付安装、场勘、培训、软件、维修、保险/责任与回收成本 | 用未含服务的硬件目标价证明商业成立 |
| 交付 | 带尾板/升降平台的车辆或等效设备；整机全程位于托盘、轮式工装或认证吊装点；沿已勘察的卸货路线进入场地 | 人工抬车、临时拆门、未验证货梯或用 E6R2 遗留收纳态已约 113kg 的警示基线把产品称为便携 |
| 安装 | 验证地面、门宽、转弯区、坡度、阈值、无线环境、充电、消防/疏散和停放；建立路线与禁区 | 到场后边用边找路线 |
| 培训 | 用户、管理员、清洁人员分别培训；每人实操停车、急停、隐私、失联、低能量和无电恢复 | 一张快速入门卡替代场地演练 |
| 日常服务 | 管理员执行开班检查与异常隔离；WorkCore 保存序列号、硬件/固件/模型版本和维修记录 | 无版本追溯地远程更新或换件 |
| 试点响应目标 | 运营时段远程响应不超过 15 分钟；场内管理员 10 分钟内可到达并建立安全隔离；需换件的技术响应目标为 1 个工作日 | 把响应时间写成机器一定能自行脱困 |
| 救援 | 平地可由授权人员使用无工具制动释放、集成牵引点/把手和专用轮式救援工装移动；斜坡或人员受困按独立预案处理 | 让用户手提、抬车、在坡上自由滑行或临时拖拽装饰件 |
| 退出 | 可停用、清除客户数据、回收设备、恢复场地并交付事件/维修摘要 | 试点失败后把原型留在现场继续非受控使用 |

试点服务 SLA 是需要测量的运营假设。若团队规模、备件、运输或保险成本无法支撑，必须重做生态位与价格，不能靠工程师无偿驻场掩盖。

## 3. 首发 ODD 与场地准入

ODD（Operational Design Domain，设计运行域）按“被证明的交集”放行；任何一个条件未知即视为不允许。首发路线必须用配置编号固化，现场改造、家具移动、施工、人流制度或软件版本变化后重新审核。

| 维度 | 首发允许 | 首发不允许/待验证 |
|---|---|---|
| 空间所有权 | 有管理者的室内或有顶棚私域，出入口和人员规则可控 | 公共道路、开放社区、任意商场/咖啡馆、无管理共享空间 |
| 路面 | 连续、坚实、可清洁的平地；材质、摩擦、缝隙和阈值已进路线档案 | 楼梯、自动扶梯、松软地、积水、冰雪、砂石、未验证地毯/排水沟 |
| 净宽 | 常规商业路线净宽不低于 900mm；局部有满足实车掉头和会车的缓冲区 | 800—899mm 仅可作为工程精度试验，不进入首发运营；小于 800mm 禁止 |
| 转弯 | 逐弯实测，按当前约 1371mm 回转包络外加人体、物品和定位裕量 | 用 CAD 中心线或静态“能塞进去”替代动态扫掠验证 |
| 坡度/阈值 | 只有在同载荷、同轮胎、同软件的制动、稳定和重复通过试验范围内才允许 | 未冻结数值、横坡、坡上驻停/恢复未验证时一律禁用 |
| 人流 | 可定义峰值、可设置让行规则，管理员能临时关闭路线 | 拥挤人群、儿童自由穿行区、无法控制的排队区或活动散场 |
| 门/电梯 | 人工保持开启且已纳入演练的普通门；同层路线优先 | 自动门、电梯、门禁联动和跨层自主通行 |
| Follow 条件 | 空载、完全收纳、A08 脚踏为 `STOWED`、主人 UWB 与视觉同时可信、主人可见、1.0—1.5m 间距、速度不超过 0.8m/s | 载人跟随、无人配送、目标猜测、失联后继续寻找、盲角追赶 |
| Ride 条件 | 受训用户主动操纵，A08 脚踏为 `DEPLOYED_LOCKED`，社区式低速上限不超过 1.0m/s；路线已验证 | 自动驾驶宣传、脚踏未正锁仍放行、娱乐性零转、未经验证的障碍/坡道 |
| 网络 | 核心停车、制动、隐私和本地上下文恢复不依赖云；网络质量只影响增值能力 | 断网即失去安全停车或暴露他人任务 |
| 环境 | 光照、温湿度、粉尘/液体、噪声、电磁环境均在已测范围 | 户外日晒雨雾能力由单个供应商 IP 等级或传感器参数代替整机证据 |

每条路线的放行包至少包含：带尺寸与禁区的地图、照片/视频、时段人流、地面/阈值/坡度清单、无线测量、充电/停放点、消防疏散关系、故障隔离点、救援路径、责任人、样机配置和有效期。

## 4. 四态端到端场景与状态机

### 4.1 首发标准旅程

首发的标准旅程不是四张静态效果图，而是一条可重复的闭环：

`停靠/充电 → Follow 收纳随行 → Ride 载人漫行 → Café 社交驻停 → Focus 专注工作 → Café 收纳确认 → Ride 离场 → Follow 归位 → 停靠/充电`

每次试验同时记录两种时间：

- **机器时间**：从有效命令到机构运动停止、正锁确认和状态发布；
- **用户端到端时间**：从用户决定切换，到物品、身体、隐私、驱动和数字任务都进入可用状态。

只优化机器动画会遗漏清桌、找摇杆、收线、放杯子、登录、失败恢复等真实摩擦。

### 4.2 四态转换矩阵

| 从/到 | Follow | Ride | Café | Focus |
|---|---|---|---|---|
| **Follow** | 主人持续可信；A08 保持 `STOWED`；路线内随行；失信停车 | 停稳并驻车；确认座面/脚踏区无物；用户取出摇杆、将同一 A08 展开并正锁、上车并通过占用确认 | 不作为首发直接转换；先进入 Ride 的停稳/授权链 | 禁止直接转换 |
| **Ride** | 停稳驻车；用户离座；A08 与摇杆收纳；座面与扫掠区清空；再授权 Follow | 用户主动操纵；A08 保持 `DEPLOYED_LOCKED`；持续检查占用、脚踏、制动和路线 | 驻车并硬件断驱动；用户双脚稳定落地后默认收起 A08；收纳摇杆；桌机构区清空；只展开单侧桌 | 禁止一步跳转；必须先经 Café，验证停车、清桌和驱动隔离 |
| **Café** | 不作为首发直接转换；先经 Ride 完成离座与收纳链 | 清空/收回单桌并正锁；确认智能脊柱低位；将同一 A08 展开并正锁；恢复摇杆；解除驻车需显式授权 | 保持断驱动；主态 A08 为 `STOWED`、双脚可落地；如用户显式选择可在净空确认后进入脚踏展开子态 | 清空两侧扫掠区；A08 默认保持收起；展开双桌；智能脊柱升起；完成身份、隐私与任务恢复 |
| **Focus** | 禁止直接转换；按 Focus→Café→Ride→Follow 退回 | 禁止一步跳转；必须先降脊柱、收双桌并经 Café 验证 | 保存/挂起任务；遮蔽工作相机；降智能脊柱；清空并收回指定桌面；A08 回到 Café 主态 `STOWED`，除非重新完成可选展开确认 | 驱动硬件禁止；主态 A08 保持 `STOWED`、双脚可落地；桌面/脊柱正锁；身份、设备、隐私和任务上下文持续一致 |

所有非标准跳转都应被状态机拒绝并解释缺少的条件，而不是靠用户记忆顺序。急停、断电、低能量和手动恢复是覆盖四态的工程状态，不伪装成第五个日常产品状态。

上述矩阵中的四个主态固定使用 E6-DFR5 A08 默认合同：Follow/Café/Focus=`STOWED`，Ride=`DEPLOYED_LOCKED`。Café/Focus 的脚踏展开是显式可选子态，不是第五/第六个产品主态，也不进入四主态 4×8、共 32 张的正式图系列。所有这些姿态使用同一套 47 个生产意图 B-Rep occurrence 和同一平台；姿态切换不得增删或替换零件。旧六发生项与 `1.890987 kg` 仅属已被替代的 DFR4 抽象，当前 47 件机构的 EBOM、材料和实测质量必须重新对账。

### 4.3 转换前后必须随身的物品

标准负载至少包含：16 英寸笔记本、平板或 A4 文件、鼠标、耳机、充电器、手机（含 Qi 在位）、一根松散线缆、带盖水瓶、开放杯、外套和包。每一件物品在每次状态转换中都要被归类为：

- 固定在认证仓位；
- 由用户明确取走；
- 被传感/互锁确认不在运动扫掠区；
- 触发转换拒绝并给出可执行提示。

不允许把“测试时先清空产品”作为现实场景。基础门槛是 0 跌落、0 夹持、0 洒液进入电气舱、0 线缆卷入、0 未固定物导致的驱动放行；发生一次即停止该配置测试并做根因闭环。

### 4.4 端到端转换验收

- 空桌机构单次变形的 P95 不超过 15 秒，同时记录带真实物品的用户端到端时间；
- 20 名目标用户在不接受实时指导的第二次尝试中，标准转换正确完成率不低于 90%；
- 所有进入 Ride/Follow 的路径均需分别证明 A08 `DEPLOYED_LOCKED`/`STOWED`、桌面、脊柱、摇杆、占用和驱动互锁不存在单点误放行；
- 所有进入 Café/Focus 主态的路径均需证明 A08 默认为 `STOWED`、双脚有落地路径、驱动硬件禁止和机械驻车成立；可选展开命令还必须单独证明净空、正锁、回收和失败退化；
- 用户端到端时间必须与当前替代流程逐人配对比较；若没有显著降低摩擦，即使机构达标也不放行产品价值。

## 5. Context Continuity：必须单独立项的核心能力

“上下文连续”不是开机快，也不是记住一个应用。一次有效恢复至少要绑定：正确用户、正确物理构型、允许的设备、最近任务/文件、窗口与显示布局、输入输出设备、网络可用性、隐私状态和未完成动作。恢复前必须先鉴权；无法确认身份时显示中性占位，不暴露任何内容。

### 5.1 计时定义

**Task Restore Time** 从用户发出一次明确恢复意图（或完成规定的 Focus 正锁且系统收到该唯一意图）开始，到用户能在正确任务中完成第一个有效输入为止。登录等待、设备重连、窗口重排、文件重开和错误恢复都计入；预先在后台打开但用户不可操作不算完成。

### 5.2 EVT 放行门槛

- 至少 30 个真实“中断—移动—恢复”循环，覆盖不少于 5 名用户、2 种主设备和离线/弱网条件；
- Task Restore Time **P95 ≤ 10 秒**，同时报告中位数、最大值、失败分布和冷/热启动差异；
- 30/30 恢复到正确用户与正确任务；跨用户内容泄漏、错误文件打开或未授权相机/麦克风开启均为 0；
- 断网时仍能完成本地身份、隐私、构型快照和最近任务的安全恢复；云能力降级必须可见但不阻断安全收纳；
- 恢复失败时保留用户数据、给出可执行回退，并能在不重启整机的情况下回到中性安全状态；
- 与“普通笔记本+推车/座椅+手工恢复”做同任务对照。若用户只感知到一张自动展开的桌子，则 Context Cartridge 尚未形成产品差异。

## 6. 低能量、失信与救援闭环

控制系统可保留 `LOW_ENERGY`、`FOLLOW_STOPPED`、`MANUAL_RECOVERY` 等工程态，但用户只需看到清晰、稳定、可执行的意图：继续、正在停车、已安全停住、需要接管、等待管理员。

### 6.1 低能量

1. 低能量阈值必须来自最坏电池、温度、载荷、坡度、老化和制动任务谱，不得只用剩余电量百分比；
2. 进入阈值后不接受新的长距离 Follow/ Ride 任务，只允许完成安全停车、必要的机构收纳、隐私关闭和受控回站；
3. 必须保留独立于主计算的制动、状态指示和无电释放路径；
4. 电量预测连续偏差、无法到达停靠点或机构无法完成收纳时，立即转入管理员救援，不反复尝试耗尽余量。

### 6.2 Follow 失信

- UWB、视觉、保护场、轮速或构型任一关键输入失信时，不猜测主人、不追赶、不自行绕行；减速并进入受控停车；
- 停车后维持机械制动，以方向明确的低亮状态提示主人从安全侧接近；
- 只有重新完成身份与环境确认，或用户切换到经验证的 Ride/手动恢复流程后才可移动；
- 每次失信保存同步日志：传感输入、置信度、制动命令、速度、位置、用户操作和恢复结果。

### 6.3 无动力与现场救援

- 在断主电、主计算失效、单驱动故障和网络中断下，现场人员仍能识别状态、隔离驱动、机械驻车和释放制动；
- 平地恢复必须做到无需抬车、无需拆壳、无需临时工具；使用结构认证的牵引点/把手和随设备交付的轮式救援工装；
- 制动释放必须是持续授权动作，释放状态具有机械/视觉指示，并防止坡上无控制溜车；
- 场地在每班运营前确认救援路线未堵、工装在位、联系人有效；每月做一次断电实车演练；
- 任何人员受困、烟雾、热失控、不可控运动或制动失效按人身安全事件处理，优先撤人和隔离，不要求保护样机。

放行前必须在基础 SKU 物理件身份对账后，使用 E6-DFR4 冻结的最重基础构型和最大验证载荷，实测平地起步/持续推拉力、坡面控制、救援时间及不同体型人员的人体风险。E6R2 遗留收纳态约 114.11kg 只能作为不得人工抬车的风险警示，不能替代新的总质量对账。没有上述证据，不得声称“一个人可以轻松移动”。

## 7. 公共可读性、隐私与礼貌

首发虽在私域，仍会遇到未受训同事、访客和清洁人员。产品的陌生感可以存在，但它下一步做什么、是否安全、是否在感知必须一眼可读。

### 7.1 隐私冻结

- 工作相机在 Ride/Café/收纳态由可见的物理隐私片遮挡；麦克风具有独立硬件静音和近场可见状态；
- 基座导航传感器与工作相机分开表达。安全移动所需传感不能被“相机都关了”的模糊宣传掩盖；
- 默认本地处理、最小留存；不做旁观者身份识别，不将原始公共区域影像用于模型训练，除非场地方与数据主体完成单独授权；
- 2m 外可辨认“工作相机遮挡/麦克风静音/正在安全感知/故障”四类状态；颜色不是唯一通道；
- Focus 恢复任何个人内容前先鉴权，用户离开或进入移动链时自动转为中性显示并关闭采集；
- 日志按安全事件、产品分析和用户内容分层，分别定义访问者、用途、保存期和删除机制。

### 7.2 空间礼貌冻结

- 默认无公共语音播报、无 RGB 表演灯、无人格化催促；必要提示优先使用方向性低亮灯语、屏幕和简短声标；
- Follow 不挤过人体缝隙、不从盲侧追赶；遇会车、儿童、排队或不确定意图时停车让行；
- 任何状态都不遮挡疏散通道；停放轮廓、脚踏、桌面和开启服务门的扫掠区进入场地地图；
- 轮胎擦地、制动、机构、风扇和提示声分别测量并与场地背景及普通滚轮行李/办公设备做 A/B，不以单个峰值分贝掩盖尖锐、重复或方向不明的声品质；
- 未受训旁观者应能找到急停/管理员提示、判断安全接近侧，并在不触碰设备的情况下绕行。

## 8. 第一印象与“神秘的是能力，不是意图”测试

### 8.1 双盲式观看流程

在不出现 WorkCore 名称、品类口号和讲解员提示的情况下，让目标用户与普通旁观者分别在 2m、5 秒观看 Follow、Ride、Café、Focus 的静止或短动作片段；随后观看 90 秒标准旅程演示。记录原话、视线、退让路径和实际操作，不能只发满意度问卷。

### 8.2 首轮冻结指标

| 维度 | 继续门槛 | 失败含义 |
|---|---|---|
| 即时状态 | 至少 80% 的参与者在 5 秒内正确判断“正在移动/已停稳/可坐或工作/不可接近运动区” | 外观隐藏了意图，旁观者要靠猜 |
| 安全路径 | 至少 90% 在 2m 外能指出安全接近侧、预计运动方向或“它已经停住” | 神秘感侵蚀公共安全 |
| 隐私/故障 | 至少 90% 在 2m 外能区分隐私关闭、仍在导航感知和故障/需接管 | 物理遮挡与灯语造成虚假安全感 |
| 好奇而不恐惧 | 至少 60% 自发询问“它还能做什么”，同时不超过 10% 因不理解运动而主动退出路径或拒绝靠近 | 要么只是普通家具，要么像不可预测的机器人 |
| 独特价值 | 演示后至少 70% 能用自己的话提到“移动后恢复同一任务/减少重新布置”，而不只说电动桌、椅子、轮椅或跟随箱 | 四态是造型拼接，Context Continuity 没被感知 |
| 不误导 | 100% 能理解它不可手提、不可自由上路、不是无人照护设备 | 叙事制造高风险错误期待 |

“被称作轮椅、椅子或行李”本身不是失败，也不得筛掉不利答案。真正要避免的是：即时意图不清、价值只能靠长篇解释，或用户在演示后仍认为它只是把现有桌椅装到轮子上。

若首轮样本显示门槛过松或过严，只能在查看完整原始数据后为下一轮预注册新阈值；不得为了让当前样机通过而回改本轮判据。

## 9. 量产前验证阶梯与放行/叫停门

所有阶段都采用“配置冻结→预注册任务与阈值→执行→独立复核→缺陷闭环→原配置复测→回归关键已通过项”的顺序。换硬件、算法、结构、路线、载荷或服务流程后，应按影响分析回退相应关口。

| 关口 | 最小样本与场景 | Continue | Hold/返工 | Stop/重定产品 |
|---|---|---|---|---|
| G0-ECO 产品存在性 | 20 名符合 ICP 的目标用户影随/日志；访问实际预算方 | 每人统计真实中断；样本中位数 ≥3 次合格中断/有效日；至少 5 份付费试点合同、预算批准或带金额/期限/责任人的书面意向 | 痛点存在但买方、预算科目或服务边界不清 | 中位数 <3；少于 5 个付费/预算意向；替代方案明显更经济 |
| G1-SITE 场地准入 | 至少 3 条真实运营路线，覆盖至少 2 类目标场所；每条有完整路线包和救援演练 | 所有 ODD 数值均落入同配置 DVPR；无需抬车或临时改造 | 个别路线可经明确工程/运营修正达标 | 价值必须依赖道路、人群、电梯或无法管理的路线才成立 |
| G2-TRANS 四态与物品 | 每条路线至少 10 个完整标准旅程，共 ≥30；20 名用户完成关键转换 | 0 安全关键事件、0 手工抬车、0 物品跌落/夹持/洒液；二次尝试正确率 ≥90%；空桌机构 P95 ≤15s | 可恢复的人因/机构问题，有明确根因和重测计划 | 四态不能在真实物品与人体条件下安全可逆，或恢复负担抵消价值 |
| G3-CTX 上下文连续 | ≥30 次真实中断—恢复；≥5 人、≥2 主设备、含离线/弱网 | Task Restore Time P95 ≤10s；30/30 正确用户/任务；0 跨用户泄漏；离线核心成立 | 非安全失败有确定修复路径，修复后全量回归 | 超过 10s、仍需多步手工恢复，或“魔法时刻”仍只是一张展开桌 |
| G4-ROUTE 运行与恢复 | 三路线各在峰/非峰、不同光照和日常污染下重复；注入失联、低能量、传感污损、断网、断主电 | 安全关键干预为 0；标准旅程成功率 ≥95%；非安全人工干预不高于 1/20 旅程；所有故障进入可解释安全态并按 SLA 救援 | 仅需收窄 ODD 或修正可诊断缺陷 | 干预/驻场成本使服务不可持续，或系统靠人持续看护才显得可靠 |
| G5-PUBLIC 可读性与隐私 | 目标用户和未受训旁观者分别测试；不预先解释品类 | 达到第 8 节全部指标；0 隐私泄漏、0 欺骗性状态 | 灯语、遮挡、声品质或交互可修复 | 场地方因旁观者风险、隐私或扰动拒绝部署 |
| G6-PAID PILOT 付费运营 | 至少 2 个设计伙伴场地，按真实合同连续运行；全部服务工时和成本入账 | 用户持续使用；买方愿意续租/扩大；单位经济含交付、救援、维修后仍有可行路径 | 需要改价、缩 ODD 或重构服务，暂停新增交付 | 无续约意愿、COGS/服务无收敛路径，或核心价值需免费工程师驻场支撑 |

### 9.1 统一停止条件

以下任一项成立，应停止扩大样机数量和营销承诺，回到产品定义；不允许用更多功能掩盖：

- 目标用户每天不足 3 次合格中断；
- 无法获得 5 个真实付费/预算意向；
- Context Continuity P95 超过 10 秒、跨用户错误不为 0，或用户只感知“桌子展开了”；
- 三条真实路线需要频繁人工扶持、抬车、追车、重配地图或临时封路；
- 低能量/失信/断电无法由受训现场人员安全恢复；
- 旁观者无法读懂运动、停车、隐私或故障，场地方因此拒绝；
- 把交付、驻场、维修、备件、保险和回收计入后，没有可解释的价格/成本收敛路径。

Stop 不等于项目永远终止。它意味着当前“人群×场景×产品×服务”的组合被证伪，下一步应缩 ODD、换 ICP、删除状态或重构价值主张，再从 G0 重新验证。

## 11. 证据包与变更控制

每个关口的证据包必须能让未参与设计的人复现结论，至少包括：

- 样机序列号、BOM/质量/载荷、结构版本、固件/模型/配置哈希；
- 预注册方案、原始数据、完整失败项、视频时间码、用户原话和偏差说明；
- 路线版本、ODD 数值、环境、人员、替代方案和服务工时；
- 安全事件、近失事件、隐私事件、缺陷严重度、根因、纠正措施和原配置复测；
- 阶段评审签字：产品、机械、电气/电池、控制/功能安全、人因、隐私/安全、制造/供应、质量/服务及设计伙伴代表。

任何会改变运动、制动、状态识别、隐私、物品扫掠、路线适配或救援的变更，都要先做影响分析并选择回归集。只修通过截图、删掉失败数据、换场地直到通过，均不构成量产证据。

## 12. 对外叙事红线

- 可以说：E6 是面向任务连续性的四态个人移动工作伴体；首发在设计伙伴的受控私域中验证。
- 证据达标后才可以说：在明确 ODD 内受限随行、载人低速移动、驻停变形和上下文恢复达到公布指标。
- 不可以说：可手提的随身行李、任意公共空间自主跟随、自动通过道路/电梯/门、无人照护、医疗获益、全天候户外、零风险或已经量产成熟。
- “神秘感”只属于隐藏复杂度、安静变形和首次发现能力；运动方向、停车、隐私、故障和接管永远不能神秘。
